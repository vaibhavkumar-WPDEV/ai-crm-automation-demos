Investigation order

  1. Open the contact's workflow history: which workflow sent it, which enrolment, timestamps.
  2. Check enrolment trigger and whether re-enrolment is ON (second run during first delay).
  3. Inspect the delay: does any branch or unenrolment criterion re-check meeting/deal/lifecycle status after it?
  4. Look for a second workflow with an overlapping trigger sending a similar email.
  5. Check the send action: marketing contact status, unsubscribe and suppression lists.
  6. Reproduce with a test contact for each path, then re-run after the fix and compare.

Fix applied in the model

  • Unenrolment criteria: meeting status no longer "booked", call completed, unsubscribed
  • Re-enrolment off while a run is active (no parallel runs)
  • If/then branch after the delay re-checks status before the send action
